# allmarket.biz Sync для CS-Cart (`allmarket_sync` 1.0.0)

Модуль обміну магазину на CS-Cart з маркетплейсом allmarket.biz. Говорить тим самим Seller API, що й
модуль PrestaShop `allmarketsync` (контракт — `../allmarketsync/docs/API.md`), тому з боку порталу
нічого додаткового не потрібно: продавець створює API-ключ у кабінеті (Інтеграції → Інтернет-магазин).

Перевірено на CS-Cart 4.17.2.SP3 Ultimate (копія comfortlife з UniTheme2, `product_variations`,
`warehouses`, Нова Пошта) проти стейдж-копії порталу. Мінімально: CS-Cart 4.11.1, PHP 7.1.

## Що вміє

| Напрям | Як |
|---|---|
| Категорії | дерево магазину → `POST /categories/batch`; відсутні на порталі створюються; панель «Розміщення категорій» з деревом порталу (`GET /portal-categories`): «Відповідає категорії порталу» (`id=X`) або «Створити всередині» (`id>X`) |
| Товари | `POST /products/batch`: назва, описи, фото (головне + додаткові), бренд (характеристика типу «Бренд»), характеристики з `id`/`value_id`, артикул, вага, URL, мета |
| Варіації | кожна варіація — окрема позиція з `group_id` = батьківський товар групи; характеристики варіації йдуть як `type: variant` і додаються до назви. Якщо у варіації не синхронізовані спільні характеристики/опис — беруться з батьківського товару |
| Ціни | ціна для «всіх покупців» з урахуванням каталожних промоакцій; `old_price` = базова або «ціна за списком», якщо вища; переводиться з основної валюти у вибрану за курсом магазину; націнка, % |
| Залишки | `products.amount`, а з модулем «Склади» для товарів з обліком по складах — сума складів вітрини; `available` враховує облік залишків, «замовлення під очікування», від'ємні залишки, нульову ціну |
| Синхронізація | за хешами: часта задача шле лише змінені ціни/залишки (`/offers/batch`), нові позиції — повною карткою; товари, що зникли з вивантаження, видаляються (`/products/delete`) із захистом від масового видалення |
| Замовлення | опитування `GET /orders` або вебхук; замовлення створюється як у «Керуванні замовленнями» адмінки: ціни allmarket.biz, вартість доставки, вибраний спосіб доставки й оплати, статус нового/оплаченого; `ack` порталу |
| Статуси | зміна статусу замовлення в CS-Cart → `POST /orders/{id}/status` з ТТН і перевізником останнього відвантаження; відвантаження з ТТН після зміни статусу надсилає статус ще раз; недоступний портал — черга `statuses`. Статуси з порталу застосовуються у зворотному напрямку |
| XML-фід | YML-сумісні `full` і `offers` (`Last-Modified` / 304) — режим «Фід» або «API + фід» |

## Встановлення

1. Завантажити `allmarket_sync-1.0.0.zip` у «Модулі → Керування модулями → Завантажити й встановити»
   (або скопіювати `app/`, `design/`, `var/` у корінь магазину й встановити модуль у списку).
2. Налаштування модуля → «Підключення»: адреса API `https://allmarket.biz/api/v1`, API-ключ і ID продавця
   з кабінету allmarket.biz. «Каталог»: мова, валюта (та сама, що в кабінеті «Валюти»), категорії.
   «Замовлення»: статуси, спосіб доставки й оплати.
3. Маркетинг → allmarket.biz → «Перевірити з'єднання». Там же: відповідність статусів, адреси вебхука
   та фідів, команди cron, журнал. Маркетинг → allmarket.biz → «Розміщення категорій» — правила розміщення.
4. Cron (сервер):
   ```
   */15 * * * * php /шлях/до/магазину/admin.php --dispatch=allmarket_sync.cron --task=all --switch_company_id=1
   0 3 * * *    php /шлях/до/магазину/admin.php --dispatch=allmarket_sync.cron --task=catalog --switch_company_id=1
   ```
   або зовнішній cron на `index.php?dispatch=allmarket_sync.cron&token=…&task=all` (адреси — на сторінці модуля).
   Задачі: `catalog`, `offers`, `orders`, `statuses`, `feed`, `all` (= offers + orders + statuses);
   `--force=1` — надіслати все й видаляти без перевірки; `--verbose=1` — журнал у консоль.
5. Вебхук (миттєві замовлення): URL і секрет зі сторінки модуля — у кабінет allmarket.biz.

## Ідентифікатори

`external_id` = `product_id` CS-Cart (рядком) і для простих товарів, і для варіацій. Замовлення шукає товар за
`external_id`, потім за артикулом (`product_code`). Якщо продавець раніше вивантажував той самий асортимент
модулем PrestaShop, ідентифікатори інші — портал створить нові позиції, старі треба видалити.

## Дані модуля

- `?:allmarket_sync_items` — хеші надісланих позицій; `?:allmarket_sync_orders` — зв'язок замовлень,
  статуси, черга; `?:allmarket_sync_log` — журнал (останні 5000 записів).
- Токени, правила розміщення, відповідність статусів, блокування задач — `?:storage_data`, ключі
  `allmarket_sync.<key>.<company_id>`. Фіди — `var/allmarket_sync/`.
- Ultimate: модуль працює від імені власника вітрини (якщо в адмінці вибрано «Усі вітрини» або консоль
  без `--switch_company_id` — від першої активної).

## Мовні файли

`var/langs/{uk,ru,en,pl}/addons/allmarket_sync.po` генеруються з однієї таблиці:
`python3 tools/build_langs.py`. Після зміни — перевстановити модуль.

## Стейдж для тестів

`tools/staging/Dockerfile` — PHP 7.4 + Apache для копії магазину. Схема, якою перевірено цю версію:

- копія коду магазину (APFS-клон) + дамп БД у MariaDB 10.11, усе в Docker-мережі `--internal`
  (без виходу в інтернет: SMS/e-mail/служби доставки копії не можуть нікому нічого надіслати),
  доступ з браузера — через socat-проксі на `localhost:8092`;
- `config.local.php` копії: БД, `http_host`, `lock_backend=database`; у БД — `storefronts.url`,
  `secure_*=N`, вітрина відкрита;
- портал — контейнер `amportal-web` з `../tools/staging`, підключений до тієї ж мережі; ключ продавця —
  `staging/issue_key.php <username>`.

Перевірено: каталог (288 позицій, 37 категорій, 45 груп варіацій), повторний запуск без змін, зміна ціни/залишку
(1 offer), вимкнення й повернення товару, склади, розміщення «Створити всередині» з перенесенням гілки на порталі,
імпорт замовлення (ціни, доставка Нова Пошта з вартістю порталу, ack), відмова для товару без залишку, статуси
accepted/shipped з ТТН, вебхук (ping, підпис, імпорт, повтор, статус, 404), фіди (200/304/403), cron-URL, сторінки адмінки.
